# Распределение работы и контрольные точки

## Всеволод - исследовательский дизайн, TLA⁺ / TLC и проверка результатов

1. Проверить базовые модели U/A на четырёх конфигурациях `(12,5,6)`, `(12,7,5)`, `(12,7,6)`, `(12,9,4)`, сохранить результаты и контрпример.
2. Расширить формальную модель несколькими работами и вариантами; проверить `spent + held <= budget` в A, отсутствие двойного принятия/списания, корректность отказов.
3. Формализовать G: две версии плана, подтверждение обоими агентами окончательной полной версии, запрет запуска вне согласованного плана и атомарный fallback. Сверхбюджетное соглашение допустимо; проверяем безопасность исполнения, а не правильность решения LLM.
4. Сопоставить трассы TLC с Python: гонка 7+6, атомарный отказ, два варианта работы, подтверждённый план и внеплановая заявка, fallback.
5. Проверять независимый аудит, `U*`, фиксированные сценарии и матрицу, метрики и парную статистику. Вместе с Платоном разметить подвыборку переговоров по `experiments.md`.

**Результат:** воспроизводимые модели TLC, таблица проверенных конфигураций и границ проверки, соответствующие Python-трассы, анализ результатов и научный отчёт.

## Платон - Python-среда, LLM-агенты и эксперименты

1. Обеспечить общий интерфейс инструментов, фаз, наблюдений и промптов по `system_spec.md`, включая приватность каталога, одинаковые окна, лимиты и пробуждения. Проверить тестами T01-T12, T19, T21-T25, T32-T33.
2. Реализовать 10 сочетаний U/A и N/F/R1/R3/R3P; провести E0. Сохранить манифесты, полные журналы и сводку baseline для первой сдачи.
3. Реализовать шесть S-вариантов по разделу 6 `system_spec.md`; проверить T13-T18, T20, T26-T31, T34.
4. На одном зафиксированном коммите выполнить полную E1 (400 базовых и 240 структурированных эпизодов), пройти критерии готовности из `experiments.md`. До test согласовать фиксацию кода, данных и промптов с Всеволодом.
5. Провести E2-E4 по точной матрице, сформировать проверяемые сводки из журналов, диагностические данные и команды запуска.

**Результат:** работающий стенд с 16 вариантами, проверенными тестами и воспроизводимыми экспериментами; `test` не используется для отладки.

## Что не меняем без согласования

Гипотезы, методы, состав сценариев, скрытые полезности, метрики, промпты и экспериментальную матрицу определяет команда. Исполнитель реализует спецификацию, не меняет её для получения желаемого результата. На dev допускаются согласованные исправления реализации с повтором затронутых сравнений. На test не подбираем настройки и не отбираем удачные seed. Результат любого корректно выполненного эпизода учитывается.
