**Следующие задачи:**

**Этап 1 (без LLM):** Сначала прочитать исправленную `system_spec.md`: теперь нужны оба порядка A/B, перестановка ролей A/B, одинаковое окно подготовки, тесты сообщений и логирование фактического перекрытия.  в существующих `src/project_d/environment/` и `simulation/` реализовать формат JSON из `data/examples/`, каталог заданий, состояния работ, бюджет, B0/B2, очередь событий и журнал. Написать `tests/test_environment.py` и `tests/test_scheduler.py`; все проверки `T01–T12` из `system_spec.md` должны проходить. Ничего ещё не подбирать на основании результатов LLM.

**Этап 2 (с LLM):** добавить `agents/llm_client.py` (тонкий OpenAI-совместимый клиент) и `agents/runner.py` (ходы агентов), обработчики инструментов и историю диалога. Реализовать B1/B3: доставка сообщений по расписанию. Сначала проверить один эпизод S1 и S2 с настоящей LLM, затем пилот E1. Сохранять ошибки парсинга и ответы отдельно от результатов среды.

**Пилотная LLM:** на Apple Silicon попробовать Ollama и `qwen3:4b-instruct-2507-q4_K_M` (в памяти модели около нескольких ГБ плюс контекст). Перед загрузкой проверить `uname -m` (для Apple Silicon должно быть `arm64`) и объём оперативной памяти. Команды после установки Ollama:

```bash
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama show qwen3:4b-instruct-2507-q4_K_M
```

В выводе `ollama show` убедиться в поддержке `tools`. Python обращается к `http://localhost:11434/v1` через OpenAI-совместимый клиент. Проверить реальный вызов `list_jobs()` тестовым запросом **до** написания полноценного цикла. MacBook Pro может быть разной конфигурации — возможность локального запуска не считать подтверждённой до проверки. Если модель или устройство не подходят, согласовать другой сервер и **не смешивать модели в одном основном тесте**.

**Готово, когда:** сначала воспроизводятся T01–T12, затем LLM без ручного вмешательства выполняет полный эпизод, журналы корректны и доступны все четыре режима.

## Что НЕ делаем сейчас

Не переносим старый симулятор целиком, не строим веб-интерфейс, не делаем несколько LLM-моделей, не добавляем отмены/возвраты, не переписываем научную постановку, не начинаем большой тест до пилота.

## Что можно взять из старого архива `project-d.zip`

- `sim/engine.py` — **идею** дискретной очереди событий на `heapq` и записи трасс; переписать под задания с вариантами и синхронные ходы двух LLM.
- `sim/pool.py` — идею раздельного и атомарного допуска; **не переносить реализацию без правки**: старый `authorize` сравнивает сумму с ранее увиденным агентом балансом, а новый контракт требует проверки **сервером** в момент запроса.
- `tests/test_race.py` и `test_atomic.py` — идеи граничных тестов; **не копировать ожидания**. Например, в старом тесте гонка возможна даже при `delay=0`, в новом контракте нулевая задержка означает немедленное списание.
- `sim/llm.py` — подсмотреть логирование и обработку ошибок, но старый агент выбирает только `spend`/`skip`; для нового набора инструментов нужен новый цикл.

Старые CSV, отчёт и результаты считаются нерелевантными новым экспериментам, пока отдельно не доказана сопоставимость условий.
