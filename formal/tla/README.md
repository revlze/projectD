# Формальные модели U/A/G

## Структура

```text
tla/
├── budget/                 # Две исходные модели U/A и их .cfg
├── protocol/               # Расширенная модель ResourceProtocol.tla
│   └── configs/            # Девять конфигураций для TLC
├── checks/                 # Сверка с Python и независимый перебор
├── results/
│   ├── python/             # Сохранённые трассы и результаты перебора
│   └── tlc/                # Полные логи TLC и сводка
├── run_tlc.ps1             # Запуск девяти конфигураций расширенной модели
├── validation.md           # Статус проверок и результаты
├── README.md               # Описание и инструкции
└── .gitignore              # Исключает временные файлы TLC
```

`budget/UnsafeBudget.tla` и `budget/SafeBudget.tla` - исходные пилотные модели (см. [validation.md](validation.md)). Они сохранены без изменений. Каждая модель имеет одноимённый `.cfg`; их удобно открывать и проверять в VS Code отдельно.

`protocol/ResourceProtocol.tla` - расширенная конечная модель исполнения. Она включает двух агентов, четыре работы, альтернативы, зависимости, две версии предложений, подтверждение v2, контроль G, его снятие и fallback. Стоимости фиксированы, бюджет задаётся в `.cfg`.

| Агент | Работа | Вариант | Стоимость | Предшественник |
| --- | --- | --- | ---: | --- |
| A | qa | full / short | 7 / 4 | - |
| A | report | full | 2 | qa |
| B | regression | full | 6 | - |
| B | ablation | full | 1 | regression |

## Границы модели

Решения агентов недетерминированы: любое корректное собственное предложение, пустой план, пропуск, подтверждение или отказ от подтверждения. Неполный план не подтверждается. Сверхбюджетный план может быть подтверждён. Пропущенный или некорректный пересмотр сохраняет последнюю корректную версию. Публикация абстрагирована барьером после двух решений, без моделирования текста и видимости отдельных сообщений. После публикации v2 содержание плана не меняется. V, раскрытые альтернативы, пользовательские приоритеты и полезность не моделируются; они влияют на выбор плана, но не на гарантии допуска. N/F/R1/R3/R3P и варианты числа раундов различаются только поведением агентов и потому здесь не разделяются.

Временные ограничения, лимиты решений, завершение агента, повтор request_id и уведомления не моделируются. Неуспешные заявки без изменения существенного состояния представлены stuttering. Допускаются все порядки принятия, commit и complete при сохранении причинности и зависимостей. Это более широкая абстракция порядка событий, чем конкретный планировщик Python; не каждая трасса модели обязана быть достижима с фиксированными задержками. Отдельные свидетельствующие трассы сверяются с Python. `DeferredCommit=FALSE` объединяет допуск и списание в один переход. При `TRUE` допуск и commit разделены.

Модель не проверяет завершение всех работ (liveness), качество координации или оптимальность. `CHECK_DEADLOCK FALSE` используется намеренно: остановка без новых решений допустима, в том числе при невыполнимом согласованном плане. TLC проверяет конечный экземпляр, а не произвольные параметры или корректность всего Python-кода.

## Конфигурации TLC и ожидаемые исходы

Все конфигурации расширенной модели находятся в `protocol/configs/`. Это варианты проверки одного и того же модуля, а не отдельные модели.

| Конфигурация (после `ResourceProtocol_`) | Ожидаемый результат |
| --- | --- |
| `U_N.cfg` | Нарушение BudgetSafety |
| `A_N.cfg` | Все заданные свойства выполнены |
| `U_Immediate.cfg` | Все заданные свойства выполнены |
| `A_S.cfg` | Все заданные свойства выполнены, G выключен |
| `A_VBC.cfg` | Все заданные свойства выполнены, G может сниматься |
| `A_VBC_Enough.cfg` | Все заданные свойства выполнены, бюджет 16 |
| `U_VBC.cfg` | Нарушение BudgetSafety, возможно даже при отсутствии соглашения |
| `U_VBC_Agreed.cfg` | Нарушение ActiveAgreementBudgetSafety, контрпример именно при действующем G |
| `U_VBC_GuardOnly.cfg` | Проверка свойств G без заведомо ложного BudgetSafety |

Основные инварианты: `TypeOK`, `Accounting`, `BudgetSafety` (кроме `U_VBC_GuardOnly` и `U_VBC_Agreed`, где вместо него проверяются соответственно свойства G и условие `ActiveAgreementBudgetSafety`), `AgreementConsistency`, `ActiveGuardSafety`, `GuardHistorySafety`, `DependencySafety`, `ReleaseValidity`, `FeasibleAgreementNoRelease`, `FeasibleGuardSafety`. `ReleaseMonotonicity`, `ReleaseRule` и `PlanFrozen` дополнительно проверяют последовательные состояния в положительных конфигурациях. `ActiveAgreementBudgetSafety` намеренно ложен для U/VBC.

`FeasibleGuardSafety` условен: только при подтверждённом плане, включённом G и стоимости всего плана не выше бюджета. В этих условиях даже U не может превысить бюджет, так как каждая работа принимается не более одного раза, допустимы только согласованные пары и снятие G не требуется. Это не утверждение о выполнимости зависимостей или обязательном завершении плана.

## Запуск

Из `formal/tla/protocol` (одна конфигурация):

```powershell
java -jar "C:\path\to\tla2tools.jar" -workers 1 -config configs/ResourceProtocol_A_VBC.cfg ResourceProtocol.tla
```

Пилотные модели можно проверить через VS Code или из `formal/tla/budget`:

```powershell
java -jar "C:\path\to\tla2tools.jar" -workers 1 -config UnsafeBudget.cfg UnsafeBudget.tla
java -jar "C:\path\to\tla2tools.jar" -workers 1 -config SafeBudget.cfg SafeBudget.tla
```

Для последовательной проверки девяти конфигураций расширенной модели из `formal/tla`:

```powershell
.\run_tlc.ps1 -Jar "C:\path\to\tla2tools.jar"
```

Скрипт сохраняет полный вывод TLC, версию Java, хеш JAR и таблицу результатов в отдельный каталог `results/tlc/<run_id>/`. Рабочие файлы TLC направляются в `.tlc/<run_id>/`. При обычном запуске через VS Code или напрямую TLC также может создать `states/` рядом с модулем. Эти временные каталоги исключены из Git; их можно удалить после завершения проверки, если не требуется восстановление прерванного запуска. Для ожидаемых контрпримеров проверяет не только код возврата, но и имя нарушенного инварианта. Не коммитить служебные состояния TLC; сохранить итоговую сводку и нужные контрпримеры.

## Сопоставление с Python

Из корня репозитория (в установленном проектном окружении):

```powershell
$env:PYTHONPATH = "$PWD/src"
python formal/tla/checks/check_python_traces.py
python formal/tla/checks/check_abstract.py | Tee-Object -FilePath formal/tla/results/python/abstract_check.txt
```

Первый скрипт исполняет двенадцать контрольных трасс на реальном `Environment`, проверяет статусы, расходы, резервы, снятие G и независимый аудит. `results/python/python_traces.json` содержит полученные события. Второй выполняет самостоятельный конечный перебор состояний абстрактного исполнения для всех допустимых итоговых планов и fallback. Он не читает TLA+ и не заменяет TLC.

Статус: все девять конфигураций расширенной модели проверены в TLC, получены шесть успешных полных обходов и три ожидаемых контрпримера. Выполнены двенадцать Python-трасс, включая воспроизведение трёх контрпримеров по существенным событиям, и отдельный перебор. См. [validation.md](validation.md).
